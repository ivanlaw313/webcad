## 5. ★ 明確 SKIP：唔准開 bug 嘅範圍 ★

### 5.1 氣動實驗室 → CFD 求解 = SKIP

本機 OpenFOAM CFD 服務跑喺**總經理部電腦**嘅 `127.0.0.1:8765`。你喺你自己嘅 Linux box，**物理上連唔到**。

見到以下**全部係預期行為，唔係 bug**：
- CFD 服務 health 顯示紅色／離線
- 「本機網絡存取被擋」提示
- CFD 工作無法提交／一直 pending
- `AeroCfdPanel`、`WindCfdVerify` 相關功能唔 work

→ 一律標 `SKIP(本機服務)`。
→ **但** §4.2 嗰啲純前端計算（面元法／VLM／BEMT／最佳化）**要照測**。

### 5.2 已知限制 —— 唔准重報

| 已知問題 | 狀態 |
|---|---|
| 瀏覽器 LBM 風洞 **GPU 模式絕對 Cd 未經驗證** | 原本「~2× 系統偏差」嗰個數唔可靠（實驗堵塞率 14–17% 且從未收斂），唔係已確認嘅求解器缺陷；動量交換公式／link 計數已核實正確；正確絕對 Cd 仍未量到，總經理處理中 |
| 瀏覽器 LBM 絕對 Cd 只係**趨勢級**（球 ~0.70 vs 理論 0.47） | 已知設計限制 |
| 轉子前飛推力偏低 **20–35%** | 已知（翼型近似） |
| CFD 全湍流模型，**自然轉捩未模擬** | 已知 |
| 多目標模板自動模式**只用第一個目標排名** | 已知 |
| `tests/` 有約 214 個舊失敗測試檔 | 內部問題，與你無關（你係黑箱 UI，唔碰 tests） |

→ 以上**唔准開新 bug**。如果你發現**數值明顯唔同於上表**（例如 GPU Cd 偏差變成 5×），嗰個係新發現，可以報。

## 6. 報告格式（沿用上輪 schema，唔准改欄位）

交付包要有：

| 檔 | 內容 |
|---|---|
| `results.csv` | **欄位同上輪完全一樣**（`case_id,group,title,variant,run_id,status,version,browser_os,viewport,zoom,started_utc,active_minutes,expected,actual,bug_ids,before_json,after_json,screenshot_paths,video_path,limitations`） |
| `bugs.json` | 同上輪結構 |
| `checkpoint.json` | **每 2 小時**寫一次 |
| `REPORT.md` | 進度摘要 + P0/P1 問題 + 各組結果 |
| `evidence/` | 截圖、下載檔、錄影 |
| `SHA256SUMS` | 全包雜湊 |

### Bug ID
**由 `BUG-201` 開始編**（避免同上輪 `BUG-001…015` 撞號）。
重驗上輪 bug 時，**沿用上輪原 ID**，status 寫 `FIXED` / `STILL_OPEN` / `PARTIAL`。

### status 取值
`PASS` / `FAIL` / `PARTIAL` / `MISSING` / `NOT_RUN` / `SKIP`
（`SKIP` 係本輪新增，用於 §5.1 本機服務同 §4.3 需憑證）

### 嚴重度
| 級 | 定義 |
|---|---|
| **P0** | 資料遺失／核心工作流完全阻塞（存檔、拉伸、開檔） |
| **P1** | 功能出錯但有 workaround；幾何／數值錯 |
| **P2** | UI／易用性／互動缺陷 |
| **P3** | 文案、翻譯、排版 |

### 每條 bug 必須齊備
1. **重現步驟** —— 由「新檔」開始逐步寫，要人跟得到
2. **期望 vs 實際** —— 有數字一定要寫數字（例如「目標 40×30，實際 50×40」）
3. **截圖**（必須）
4. **before/after JSON**（如適用）
5. **版本欄一定寫** `v2.14` / `index-D22tN-jb-r2.js`
